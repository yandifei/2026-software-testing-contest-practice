### Luhn 的 int 溢出不能推翻等价性

设原版循环结束的 Java int 值为 s，变异版为 m。两者每轮使用相同的贡献项，int 加减按模 2^32 回绕，故 m ≡ -s (mod 2^32)。

1. s 不等于 Integer.MIN_VALUE 时，Java 有符号表示中的 m 就是普通整数 -s。s 被 10 整除当且仅当 -s 被 10 整除；负数余数的符号不同不影响“是否等于零”。
2. s 等于 Integer.MIN_VALUE（-2147483648）时，回绕后的相反数仍是其自身，两个结果都为 -2147483648，余数都是 -8，均被拒绝。
3. s=0 时 m=0，均被接受。没有其他特殊值。

因此超长字符串导致溢出、Unicode 数值字符导致非标准贡献值、负贡献值，都不能区分此变异。证明不要求每个贡献值非负或不发生中间溢出。若解析/分配/数位计算在循环之前失败，两版仍执行相同路径；不能借资源耗尽或速度差代替语义区分。

### Verve 的有限输入分区

令 L=506099、U=506198，所有正常解析得到的 int 可分为 x<L、x=L、L<x<U、x=U、x>U。原方法等价于 `L <= x && x <= U`。上表 7 个变异在这 5 类中分别仍返回 false、true、true、true、false。两次循环使用方法内新建数组和局部 int，不存在两次读取发生状态变化的条件。

现有测试已经包含 L-1、L、L+1、区间内部、U-1、U、U+1 和注释中第二号段的端点。继续追加同类字符串不会创造可达边或可区分结果。

## 可复用判断方法

- 先提取报告中的“类、方法、算子、字节码 index、状态”，再判断差异发生点、影响传播路径和最终可观察量；不能只看源码行号或覆盖率。
- 给不可达边写出入口路径谓词。若要到达该边同时要求 x 属于集合且不属于同一集合，输入搜索应停止并保留证明。
- 给等价变异做全输入分类，特别检查 Java 溢出、负零、NaN、异常和对象状态；“尝试很多输入未杀死”不构成等价证明。
- 重复循环可能补偿第一轮变异；真正的单次控制流修改也可能在业务输出上被后续计算遮蔽。
- 原始分支率和原始 KILLED/总数必须保留。可以另记已分析的不可达/等价数量，不能将其自动扣除后称作官方 100%。
