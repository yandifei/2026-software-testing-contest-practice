# Credit：允许白盒及字段反射后的可行性复核

复核日期：2026-10-31。对象：现有原题源码、原始 JaCoCo 236 分支和 PIT DEFAULTS 272 变异的统计范围。此文仅分析可行性，没有运行 Maven、改变测试或提交；不能据此把原始双 100% 目标标为已完成。

## 最小不可实现证书

只需要下面两个反例，就能否定“同时实现原始分支覆盖率 100% 与原始变异杀死率 100%”，无需依赖其他存活项的分类：

1. **分支障碍：TypeChecker.checkType 第 20 行。** 局部变量 type 在第 17 行被赋 null。每个把它赋为非 null 的代码路径都立即执行 break，直接跳出循环，不会再计算 while 条件。因此条件求值时 type 恒为 null，while 的 false 边没有合法执行路径。字段反射不能更改当前调用栈中的这个局部变量。
2. **变异障碍：Validator.validate 第 64 行返回 true。** 原版在局部 isValid=false 时先抛异常；正常到达 return 时 isValid 恒为 true。变异仅把 return isValid 换成 return true，原版和变异版的返回值、异常及全部实例字段均相同。方法没有在返回处调用任何用户可替换的回调。即使允许读写 private 字段，这个变异仍然不可区分。

在原源码、原控制流、原报告口径不变时，一个这样的分支和一个这样的变异已经足以阻止原始双 100%。把“用反射覆盖私有状态”扩展成“读写调用栈局部变量、替换指令或检测变异体”，已超出本次允许的测试手段。

## 字段注入逐类排查

| 对象 | 反射可以改变/观察的部分 | 为什么不能打开现有障碍 |
| --- | --- | --- |
| VerveValidator | 私有 creditCardNumberList，可注入自定义 List<Integer> | parseIIN 在两个扫描开始前执行一次，共读取 6 个元素，最终返回一个局部 int。无论 List 是稳定、可变、有副作用还是抛异常，两版的这个前置过程相同；之后两个循环不再读取字段或 List。IIN 与 IINRange 都是当前栈帧内的局部值。 |
| LuhnValidator | 本类没有实例字段；子类可重写 sumOfDigits 并记录调用 | 所有重写方法调用都发生在累积前，调用次数、顺序及参数在原版和该变异版相同。tempArray 填充完成后才执行纯局部 int 累积；没有回调可以观察中途 sum。子类字段的最终状态相同。 |
| Validator | creditCardNumber、expirationDate、expirationYear、expirationMonth、CVV | validate 使用 creditCardNumber 构造并调用局部 LuhnValidator，没有可注入的 luhnValidator 字段；isValid 也是局部 boolean。其他字段不参与该返回点。即使改换字符串或置 null，也只是让两版在同一前置路径成功或异常。 |
| TypeChecker | 没有用于这段控制流的实例字段 | checkType 每次重新定义 type；字段反射、构造器反射不能使其从非 null 进入 while，也不能取消赋值后的 break。 |

异步更改 Verve 私有 List 也无效：即使恰好影响了 parseIIN 的结果，进入扫描后已得到不可变的局部整数快照。后续执行既不重新取 List，也不调用其方法，不存在“第一轮读取 A、第二轮读取 B”的机会。

## 九个变异在扩展观察范围下的结果

### Verve 的七个变异

令 x 为 parseIIN 正常返回的任意 int，L=506099、U=506198。原代码两次都扫描 [L,U]，只在第一次未命中时进入第二次。七个存活变异分别删除第一/第二次扫描、删除命中判断、删除第二次入口判断，或把相应上端点条件由 <= 改为 <。

- 改变第一轮后遗漏的命中由未改变的第二轮补回，包括唯一上端点 U。
- 改变第二轮时，第一轮已经判定 x 不属于整个 [L,U]，第二轮不可能增加命中。
- 循环只修改局部 i 和局部 hasAllowedIINRange，不修改实例字段，不调用可覆盖方法，也不访问注入对象。

因此返回结果与字段快照均等价。反射没有增加可区分信息。边界输入、非法前缀、自定义 List、并发替换字段都不改变上述穷尽分类；解析异常也发生在变异点之前。

### Luhn 的累加改累减

tempArray 在变异点之前已经构造完毕。原版从 0 累加全部项，变异版从 0 减去全部项。Java int 模 2^32 回绕后，两者互为加法逆元。

- 对 s != Integer.MIN_VALUE，变异结果为普通整数 -s；s%10 是否为 0 与 (-s)%10 是否为 0 相同。
- 对 s == Integer.MIN_VALUE，回绕后仍为自身，两版 `%10` 都为 -8。
- 对 s == 0，两版都返回 true。

纯累积阶段没有写任何字段。白盒反射可以读取字段，却不能从对象中读到这个栈局部 sum。重写 sumOfDigits 只改变累积前的相同贡献项，对任意 int 贡献项，上述证明仍成立。

### Validator 的返回 true

见最小证书：原版到正常返回位置时，局部 isValid 已被控制流证明为 true，且两版没有不同字段写入。private 字段的可见性不影响这个事实。

## 原始指标的限制

在限定的观察方式下，三个缺失分支仍然不可达：TypeChecker:20、TypeChecker:56、VerveValidator:62。九个存活变异仍行为等价，包含字段反射观察和上述可注入对象的副作用观察。因此可给出的上界仍是分支 233/236、KILLED 263/272；这个结论没有修改分母。
