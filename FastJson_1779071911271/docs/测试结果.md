## 为什么原始变异杀死率不是 100%

所有 557 个原始变异体都保留在分母中。最后 13 个存活项逐项分析如下：

| 文件与行号 | 数量 | 存活原因 |
| --- | --- | --- |
| JSON.java:1204、1221、1226、1247、1252、1254、1276、1278 | 8 | 原路径返回 `false`，PIT 将返回值替换为 `false`；值完全相同。包含 finally 的字节码使这些无效果替换仍出现在报告里。 |
| JSON.java:257 | 1 | 去掉已经是 JSONObject 时的快捷返回，后续 `JSON.toJSON` 对同一个 JSON 实例仍原样返回，结果及对象身份相同。 |
| JSON.java:552 | 1 | 输入流入口省略 null 字符集默认化后，调用的字节数组入口仍在 445–446 行执行同样的 UTF-8 默认化。 |
| JSON.java:453 | 1 | UTF-8 解码长度为 0 时，原逻辑传入空字符串并由 372–373 行返回 null；边界变异直接返回 null。负值及正值的行为也一致。 |
| JSONObject.java:176 | 1 | 去掉 null 值快捷返回后，`TypeUtils.castToBoolean(null)` 仍返回 null。 |
| JSONArray.java:287 | 1 | 同上。 |

上述判断基于当前项目及 Fastjson 1.2.70 依赖的控制流和返回行为。
因此这里报告真实的 **97.6661%**，没有把“人工认定等价项后的比例”包装成原始 PIT 100%。
仅 8 个 `false → false` 项就足以说明：保持当前变异集合时，不可能通过增加有效行为断言使原始比例达到 100%。

此前可检出的存活项已补充测试，包括前向引用、类型转换身份、代理返回类型、GB18030 解码容量、
空切片越界、控制字符、缓冲回收、空输入分配开销以及自定义反序列化校验策略。
流扩容测试加入读取进度断言，缺失扩容的变异现在快速失败；最终没有依赖超时计分的变异。

## 已复现的生产缺陷及兼容性问题

测试保留现有实现，以下问题均没有在本次任务中修改生产代码。

1. **迁移包名后的 JSONObject 直接转换失败。**
   `JSON.parseObject("{}", Feature.OrderedField)` 将 Alibaba 的 JSONObject 直接转换为
   `net.mooctest.JSONObject`，抛出 ClassCastException；无 Feature 的重载有转换步骤，可以正常返回。
   `JSONObject.getJSONArray` 对 `"[1]"` 字符串也存在相同的包类型不兼容。
   证据：`JSONParsingTest.objectParsingWrapsMapsAndReportsNonObjectInput`、JSONObjectTest 的字符串数组测试。

2. **多层泛型替换丢失容器层级。**
   对采用实际类型参数构造器的 `List<List<List<T>>>`，递归处理直接返回内层结果，
   得到 `List<List<String>>`，丢失一层 List；遇到 Map 的内层参数时还会丢失 Map 及其他参数。
   证据：TypeReferenceTest 中两个 `characterizationRecursive...` 测试。

3. **嵌套类型参数消耗没有反馈到外层索引。**
   `Map<List<K>, V>` 使用 String、Integer 替换时，嵌套 List 消耗的索引没有返回，
   外层 V 再次使用 String，得到 `Map<List<String>, String>`。
   证据：`characterizationNestedConsumptionDoesNotAdvanceTheOuterReplacementIndex`。

4. **局部自定义序列化器在 toJSON 的回退路径失效。**
   `JSON.toJSON(value, config)` 查询局部序列化器后，其非 JavaBeanSerializer 回退路径又调用
   使用全局配置的 `toJSONString(value)`，忽略已传入的局部序列化器。
   证据：`JSONUtilityTest.characterizationNonBeanSerializerFallbackIgnoresTheSuppliedSerializer`。

5. **二维基本类型数组的 Java 反序列化被错误拒绝。**
   `SecureObjectInputStream.resolveClass` 将 `[[I` 规范化为 `I` 后交给 autoType 检查，
   导致合法 `int[][]` 类型被拒绝；同一流程的一维 `int[]` 可解析。
   证据：`JSONObjectSerializationTest.resolvesOrdinaryClassesAndPrimitiveAndReferenceArrayDescriptors`。

6. **JSON 基类的集合转换快捷路径缺少实例类型校验。**
   自定义 JSON 子类即便没有实现 List，调用 `toJavaObject(List.class)` 仍直接返回该实例，
   调用方按 List 接收时会发生类型转换错误。
   证据：`JSONMutationRegressionTest.characterizationBaseJsonCollectionShortcutsDoNotValidateReceiverType`。

使用 JDK 不可变集合的原生序列化还受到 Fastjson 对 `java.util.CollSer` 的限制；
正常往返测试采用可序列化的 ArrayList/HashMap/LinkedHashMap，避免把依赖兼容性失败误当成测试夹具错误。
