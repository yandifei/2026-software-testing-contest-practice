# 白盒补测：扩大状态控制与观察范围

适用：公开接口测试仍受私有状态或不可观察字段限制，且用户明确要求进一步本地研究；正式参赛上传另按当场规则确认反射许可。本地使用白盒方法的授权不等于组委会许可。复用单题经验前先明确本轮观察范围。

## 控制性和观察性分别处理

| 缺口 | 可用方法 | 验证与边界 |
| --- | --- | --- |
| 时钟/私有计数器决定分支 | 对有明确有效域的计数器设边界种子，调用原方法 | 保存原状态，try/finally 恢复；不改变系统时间或运行时代码 |
| 内部计数更新未被公开输出使用 | 只读观察字段，检查成功、拒绝、连续调用后的状态 | 不用反射替换被测运算，不构造破坏对象不变量的状态 |
| ±0 被公开兜底值遮蔽 | 通过真实 setter 写入，读取字段的原始位模式 | 负零是参数自然产生的状态；同时保留公开接口的行为断言 |
| 重复局部循环、恒真局部条件 | 建立路径条件证明 | 修改对象字段不能修改已经确定的方法局部值；白盒测试也不保证可达 |
| 在边界把值重新赋给自己 | 证明状态与结果相同 | 扩大状态观察范围不能区分相同状态，无需反复重跑 |

不要把“源码文件没改”当成足够条件：替换运行时字节码、修改 JaCoCo probes、探测 PIT mutant 身份然后人为失败、篡改 XML 或屏蔽统计项，都不能证明原程序行为被有效测试。只读源码哈希同时配合真实调用和原始报告，才形成可解释的证据。

## ID 的时间区间判定

对时间与计数器组合的 ID，不硬编码某一时刻，也不依赖 sleep 等待时间前进。先读调用前后时间，给内部计数器一个已知有效种子，调用一次，然后检查结果是否能解码到这段时间区间及正确的计数值。精确预期来自 ID 的位编码规则与受控计数状态，不由被测函数生成。

它是对功能结果的时间区间判定，不是以耗时差异杀变异。仍需说明系统时间突然回拨可能使区间假设失效；并发使用同一计数器时还要明确隔离策略。不能把当前默认串行成功外推成任意并发环境都安全。

所有共享状态写入放在 try 中，finally 恢复；验证日志既要确认行为断言通过，也要确认没有遗留共享状态。异常路径不会因为测试失败就跳过清理。

## 报告版本与不同观察范围

“公开接口版本”与“本地白盒版本”是不同的测试范围。记录两者的源码/POM、测试哈希、分支和原始变异分子/分母，注明新增杀死项对应哪个测试、增加的是输入可控性还是状态可观察性。

不能将白盒版的更高覆盖率包装成所有环境的可移植保证；也不能因为白盒版仍未满分而丢弃它已检出的真实差异。保留已验证的提升，同时明确整体双 100% 目标是否达成。

## 后续研究问题

- 对象状态能否由公开调用构造、由有效白盒输入构造，还是必须破坏不变量？三者应分别建模。
- 在时间回拨、并发访问、计数器溢出下，如何构造独立而稳定的位编码判定？需要实际反例和隔离验证。
- 存活变异可否被精确归类为输入不可控、差异不可观察、语义等价或资源边界？先保留未解决项，避免把缺证据说成等价。
- 对私有字段读取带来的测试耦合，能否用公开模型/状态转换性质替代？收益是更稳健的回归测试，不能靠扩大计数口径替代真实检出。

Credit 白盒复核确认：TypeChecker 的局部变量赋非 null 后必立即 break；Validator 正常返回前已排除 false。这一不可达分支和这一等价变异就足以阻止原始双 100%。字段反射无法打开这两处局部控制流，也无法区分恒为 true 的返回值。
