# 白盒研究：技术可行性与规则许可分开

## 1. 判断实际改变了什么

白盒不是一个整体许可。对每个手段分别记录：调用入口、对象如何构造、被替换的代码/返回值、原实现是否能到达、当前规则依据、观察范围。本地研究授权不等于赛事认可；POM 含 Mockito 不等于可以模拟任何被测类。

| 手段 | 应核对的边界 |
| --- | --- |
| 真实公开输入/调用序列 | 类型允许不等于业务允许；非法输入可测拒绝行为，并注明范围 |
| 真实构造器接受的特殊值 | 区别于 mock 绕过构造器；前置校验仅在某入口成立时，不外推到所有入口 |
| 反射调用真实方法/读取字段 | 扩大入口或观察范围，单独核对规则及不变量；不能把私有入口结果说成公开链行为 |
| 设置计数器、清理缓存 | 状态是否有效、可否真实建立、许可依据；恢复状态只解决隔离，不证明许可 |
| 外部服务/时钟/端口替身 | 是否为允许替换的外部边界，是否真实执行本轮被测逻辑；不能替换正在测试的方法 |
| mockStatic/mockConstruction | 若替换被测或内嵌依赖逻辑来打开原本必抛/不可达路径，不能用于禁止此行为的比赛 |
| mock record/enum、伪造不变量 | 与上述运行时改变按同一行为标准判断；不能因为 API 名称不同放行 |
| 改报告、减分母、检测 mutant 身份后失败 | 不构成有效检出，不用于成绩或交付 |

2026-11-15 题包禁止干预函数返回及改写运行逻辑人为提升指标。GPT Math 后期替换 DynamicFunctionCompiler.compile 返回值、构造模拟 ComplexExpression 的具体行为与此冲突。此结论针对实际替换行为，不是一刀切认定所有 Mockito 使用均违规。

## 2. 可达性标签

分别写明“公开真实路径”“真实对象的私有入口”“受控外部环境”“破坏原不变量/替换被测实现的实验”。只有前提和规则已明确的版本才进入提交候选。标注“环境可达”不能把不允许的行为变成允许。

未知许可时继续做明确允许的测试，将受限手段和目标缺口单列；不要为了最后几点覆盖率自行扩大边界。历史参考材料声称“官方认可”但缺原件/适用范围时视为未核实，不覆盖当前题包。

## 3. 状态、时间与观察

优先真实 API，状态写入必须保存原值并 finally 恢复；共享运行还需隔离。时钟相关结果使用调用前后区间和独立编码规则，避免硬编码当前时间、sleep 碰时序或极短阈值。

对象身份、scale、原始浮点位可揭示值相等下的差别，但需说明该差别属于契约还是现状刻画。测试不要依赖未经保证的对象缓存/分配策略来伪称业务正确性。

白盒仍不能改变已确定的方法局部变量条件；相同状态赋回自身也不会因读取更多字段变成可区分。证明要限定入口和观察域。

## 4. 历史实验如何使用

2026-10-31 Research 记录：公开接口 KILLED 279/305；设置有效计数状态/读取字段的白盒版 284/305，分支 240/240。这是历史记录，本次未重跑，不作为新比赛许可或成绩证明。

2026-11-01 的旧记录包含 mockConstruction 打开卡校验遮蔽路径、MockedStatic 打开数学必抛路径、mock record/enum 构造非法状态。它们只能证明替换环境可能提高本地计数；撤回旧文“依赖存在、仅改测试代码所以合规/官方认可”的推断。没有可核验规则原件时不延续其许可结论，也不把这些实验混称“真实输入层”。

可复用的是研究问题：入口改变了什么、差异是否传播、能否用真实合法输入产生同样差异。具体数字和历史实验条件可见 [覆盖研究](coverage-mutation-research.md)，正式提交遵守本轮规则。
