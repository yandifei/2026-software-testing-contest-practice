# 从题包到可核验交付

## 1. 固定输入与范围

记录用户任务类型（增补/独立重写/研究/提交/复盘）、工作目录、题目、截止时间及当前规则。原始题包只读，保留 ZIP 哈希；开发副本不继承 target。用户负责下载/解压时不重复操作。

核对 java 与 Maven 实际 JDK；只设置当前构建进程的 JAVA_HOME/PATH。从可信题包建立 `src/main` 和 `pom.xml` 基线。题包如另有配置/资源禁改要求，一并保存哈希。旧报告只能作为历史参考。

## 2. 从模块清单到有断言的场景

对全部生产包建立“模块—入口—状态—场景—独立预期—负责人”清单。先发现未测模块，别只延续旧题熟悉的类。

- 正常、阈值相等、相邻边界、短路右侧、异常及失败后状态分别考虑。
- 每批测试同时提供可观察断言：结果内容、状态改变、拒绝理由、必要的异常消息。对象身份/scale 只有在目标契约或明确刻画范围内才断言。
- 复杂算法使用不同算法的小规模参照，随机行为使用规则允许的受控输入。
- 不确定 API 可先做最小探针，探针只说明实际行为；再依据规范、手算或独立模型确定 expected。发现题包缺陷时明确写成现状刻画，不将错行为包装为正确需求。
- 按缺口大小、区分输入可行性、评分权重（若已知）、预计构建成本排下一批。没有权重也不等待停工，不自造 25% 默认值。

## 3. 一轮构建形成一份完整证据

1. 冻结测试文件并记录 SHA-256；本轮运行期间不编辑。
2. 确认该副本无其他构建写入。按 POM 生命周期从干净输出运行 JUnit/JaCoCo，再执行原 PIT 目标。直接 PIT goal 是否编译以该插件/项目配置为准；本题配置必须先编译测试。
3. 等进程退出，保留完整日志与退出码。失败时定位首个有效诊断，不只看日志尾部，不重复相同失败命令。
4. 检查 Surefire 实际发现数 > 0，失败/错误为 0，跳过项有解释；按本轮发现的类清单统计嵌套/参数化用例，不按注解数量推算。
5. 严格解析 JaCoCo/PIT XML，核对预期报告集合、生产目标、算子、变异身份集合与本轮编译产物。相同分母不代表相同集合。
6. 再核对测试哈希未变，将完整报告及哈希保存到项目外的本轮目录。未冻结或缺来源记录的历史文件仅称“现存产物读数”。

示例（路径和 JDK 版本由本题决定，命令逐条执行）：

```powershell
$env:JAVA_HOME = "<本题 JDK 目录>"
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
mvn -version
mvn -B clean test
mvn -B org.pitest:pitest-maven:mutationCoverage
python <skill>/scripts/jacoco_report.py target/site/jacoco/jacoco.xml 0
python <skill>/scripts/pit_robust.py target/pit-reports/mutations.xml summary
```

clean 被锁时先识别锁所属进程；不要终止无关进程，不直接降级到含旧 class 的 test。可在新的隔离副本用同一冻结测试重新构建。删除/移动输出前验证绝对路径位于本轮工作区。源文件无某类但报告有该类，是陈旧产物线索，仍需查编译输出、继承及配置，不凭类名断言原因。

报告损坏或条数异常时先区分未结束、局部目标、不同配置、截断/拼接。保留原件；诊断抽取不修复正式证据。问题处理后有理由再跑完整构建，不能硬套历史分母 1320/2528。

## 4. 缺口与版本迭代

用 JaCoCo 找未执行路径，用 PIT 区分未覆盖和断言未检出。每批新增测试记录目标变异、候选输入、原/变异预期差和实际状态；具体方法见 [研究](coverage-mutation-research.md)。

重写或合并后按 [并行集成](multi-agent-integration.md) 对账新增与丢失的杀死项。旧版数值较高不能自动覆盖用户要求的新版本；新版总体更高也不能隐瞒局部回退。

为最终全量验证、材料校验和上传保留时间，以本机实际耗时估计。到集成截止先冻结已通过的版本；子代理失败时保存断点并由主执行者接管明确缺口，不把代理汇报当完成。

## 5. 打包

使用项目外的交付目录，先复制冻结的独立 Java，再调用：

```text
python <skill>/scripts/verify_baseline.py <项目> <可信基线.json> --test-path <本题测试相对路径>
python <skill>/scripts/package_project.py <项目> <项目外ZIP> --java-file <独立Java> --max-bytes <当场ZIP上限字节> --baseline <可信基线.json> --test-path <本题测试相对路径>
```

脚本参数按 `--help` 核对。2026-11-15 题包的单文件路径为 `src/test/java/net/mooctest/StudentTest.java`，需要完整 target 及两套报告；此结构不能自动推广到所有赛题。Java 槽容量也需单独核对，MB 的字节口径按平台实际限制。

验包包括：根结构、必要原文件、单测试文件、报告完整性、ZIP CRC、全清单及每个文件字节、独立 Java 与包内 Java 一致、容量。包不能包含自身、其他题、缓存、诊断草稿。这些结构检查不能代替第 3 节的运行来源证明。记录填在 ZIP 外的 [交付记录](../assets/delivery-record.md)。

## 6. 提交与结束

仅在用户要求的阶段提交。按 [评分与回执](scoring-and-submission.md) 操作当前已观察页面，上传同一冻结版本并保留回执。不要以“选择成功”代替提交成功，也不要把别的会话已有提交算成本会话成果。

输出实际完成阶段、JUnit 计数、四类指标分子分母、残余分类与交付版本；平台评分中/未知单列。用户改为复盘时停止比赛修改与重交，保存现场做证据分析。
