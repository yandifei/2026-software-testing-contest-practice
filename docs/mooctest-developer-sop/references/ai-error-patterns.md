# 推理失误模式：下结论前的自检清单

适用：准备说出"等价""不可达""已提升""合并收益有限""跑完了"之前对照。每条是"症状→真实情况→检查法→本次代价"，来自 2026-11-15 省赛的真实失误；模式可迁移，具体数字不可迁移。

## 1. 用体量代替测量

- **症状**：4516 行、350 个测试的套件"肯定比 49 个测试的强"，直接以它为骨架。
- **真实**：那份套件行覆盖 72.67%、分支 79.80%，短套件是 79.98% / 83.94%。
- **检查法**：任何"谁更好"先给同口径三指标（行/分支/KILLED），再谈取舍；文件大小、时间、来源都不是证据。
- **代价**：按直觉单选会丢掉短套件独有的覆盖，实测合并后分支再多 7.3 个百分点。

## 2. 用聚合数代替身份集合

- **症状**：按包取两套件的最大杀死数相加，得到"并集上限 1813"，据此判断合并收益有限。
- **真实**：并集 2058（补上 333 个互补项），因为两套杀死集合大量不重叠。
- **检查法**：并集只能由 `(class, method, descriptor, mutator, indexes)` 集合计算；`max(|A|,|B|) ≤ |A∪B| ≤ |A|+|B|`，逐包取最大再求和是**下界**。结论里必须标"下界/上界/待测"。
- **代价**：差点因为"估不出收益"放弃本场最大的一笔增益。

## 3. 用语言记忆代替版本核对

- **症状**：打算把被移植套件包进 `@Nested` 内部类，并断言"内部类不能有 static 成员，必然编译失败"。
- **真实**：JDK 16 起（JEP 395）已放开这条限制；本场题包是 JDK 21，被移植套件里原本就有 `@Nested` 类声明 `private static` 字段与方法的实例，编译通过。真正的风险是**生命周期**：外层 `@BeforeEach` 会串进内层，改变被移植套件的行为；而它在 JDK 16+ 上不会报错，没有编译器兜底。
- **检查法**：任何"语言层面会失败"的推断，先核对 `java -version`/`mvn -version` 与语言版本对应的变更点，再去源码里找同类写法是否已存在；形态选择按 [套件移植](suite-porting.md) 第 4 节的表格逐项判。
- **代价**：本次靠"会编译失败"这个错理由做了对的选择（平铺），但理由是假的——换到无钩子、只有 static 成员的场景就会给出错误结论。

## 4. 用方法名代替实现阅读

- **症状**：断言 `register(instance, true)` 返回 `true`（"我刚注册，当然成功"）。
- **真实**：`getInstance(name)` 已经把它注册进 map，`containsValue` 命中后返回 `false`。用例直接失败。
- **检查法**：涉及注册表/缓存/单例，必读三件事：谁写入、谁清理、判定用 `containsKey` 还是 `containsValue`。
- **代价**：一次测试失败 + 一次改期望；更危险的是把"失败"误判成实现缺陷。

## 5. 用"分支里有 return"代替"实际可达行为"

- **症状**：认为 null 字面量比较分支会返回布尔结果，于是断言返回值。
- **真实**：该分支把整串公式当运算符传给比较函数，恒抛 `AbnormalOperation`；它内部的 `return` 类变异永远不可观察。
- **检查法**：判定"可观察"前先真跑一次该输入，记录实际抛出的异常；不要只读 `return` 语句。分支内第一个方法调用就可能终止它。
- **代价**：两个变异被误列入"可杀死"，白写断言。

## 6. 用工具回执代替真实进程状态

- **症状**：取消后台构建任务后，认为构建已停止，直接开始新一轮。
- **真实**：被杀的是包装进程，`java`/maven 子进程仍在往同一个 `target/pit-reports` 写：`mutations.xml` 标签错乱、`index.html` 被旧运行覆盖。
- **检查法**：按项目目录匹配 `java.exe` 的 `multiModuleProjectDirectory`，确认匹配数为 0 再重跑；重跑前记录报告文件长度与哈希。
- **代价**：一整轮 19 分钟的 PIT 报告作废，只能重跑。

## 7. 用记忆代替 Schema

- **症状**：按属性读取 PIT 的 `lineNumber`/`mutator`，217 条 NO_COVERAGE 的行号全为 `None`，差点得出"未覆盖项没有行号"的错误结论；按 `method` 找 JaCoCo 行覆盖得到 0 条。
- **真实**：PIT 的行号/算子/indexes 是**子元素**（XML 属性用单引号）；JaCoCo 的 `<line>` 在 `package/sourcefile` 下，`<method>` 只有 `counter`。
- **检查法**：统计脚本先做字段非空率自检（行号非空率、各状态计数之和 == 总数、类数 == 报告页数），非空率异常先修解析器，再谈指标。
- **代价**：两次统计返工，一次错误中间结论。

## 8. 用类型直觉代替签名核对

- **症状**：`when(calculator.compileBigDecimal(...)).thenReturn(mock(NameExpression.class))`。
- **真实**：该方法返回 `PackExpression`，编译失败。
- **检查法**：mock/断言前读声明；编译器信息优先于自己的类型记忆。
- **代价**：一次全量构建前才发现，返工一轮。

## 9. 用推算代替对着实现手算

- **症状**：把区间乘积 `3,4` 的期望写成 12。
- **真实**：实现按步长把右端截断到 3，只乘一次，结果 3；换了 `2,6` 才是 48。
- **检查法**：区间、步长、取整、归一化、舍入类预期，必须对着截断与舍入代码手算；选能区分边界的输入。
- **代价**：写错的 expected 会变成"按实际输出改期望"的入口，那是更严重的错误。

## 10. 用"文件存在"代替"报告新鲜"

- **症状**：看到 `index.html` 有数字、`mutations.xml` 能读，就当本轮结果。
- **真实**：`<mutations partial="true">`、中途截断、并发写都能"存在"；mtime 早于最后一次构建即不新鲜。
- **检查法**：报告时间 ≥ 构建结束时间、XML 严格可解析、总数与 PIT 控制台 `Generated` 一致、变异身份无重复——四条缺一即不用。
- **代价**：本轮曾拿到被并发写坏的 XML，必须整轮重跑才能给出可核验数字。

## 11. 被提问语气带偏

- **症状**：用户问"为什么这么久"，就想跳过全量复跑直接宣布结果。
- **正确做法**：先给已实测的数字与依据，再说明还剩哪步验证；提速靠分层反馈（[研究](coverage-mutation-research.md) 第 11 节），不靠省掉证据。
- **代价**：省一次 19 分钟，换来一个不可核验的结论，等于没做。

## 12. 用旧等价清单代替重验

- **症状**：上一轮报告写“剩余 35 条全部等价”，本轮直接继承，不再投入。
- **真实**：对长度窗口与奇数长度循环做边界复攻后，其中至少 7 条可被真实输入杀死：`MaestroValidator`/`MaestroUKValidator` 的 12 位与 19 位边界、19 位 Luhn 校验；剩余从 35 降到 27。
- **检查法**：继承的“等价/不可达”一律标为**假设**；先复攻值域边界（等值点、±1、长度上下界、奇偶、空串/空白/null、构造器禁止组合），给不出反例才保留“已攻击但未证明”。
- **代价**：少 7 个击杀（约 0.5 个百分点），并会把错误结论传给下一条执行线。

## 13. 用分支覆盖代替变异强度

- **症状**：GLM 的 card 套件分支 99.16%、815 个用例，被当成“最完整”的骨架。
- **真实**：同一套件 PIT 只有 721/1320（55%）——大量用例没有断言或重复同一路径；deepseek 247 个用例反而 1285/1320（97%）。
- **检查法**：选型必须同时看 KILLED/总数与 test strength；**分支高而击杀低 = 断言弱**。用例数、行数、来源都不参与排序。
- **代价**：若按“分支+体量”选型，会丢掉约 564 个本可继承的击杀。

## 14. 用并发跑分代替稳定复现

- **症状**：为省时间加 `-Dthreads=4` 跑 PIT，直接把该次结果写进对比表。
- **真实**：同一份 580 用例文件，4 线程出现 23 个 `RUN_ERROR`、KILLED 2397；单线程 0 个 `RUN_ERROR`、KILLED 2419。PIT 控制台会把部分异常状态计入 Killed，口径进一步混淆。
- **检查法**：并行只用于探索方向；**正式分子分母必须单线程独占一次完整运行**，并严格分列 KILLED/RUN_ERROR/TIMED_OUT。
- **代价**：多跑两轮约 6 分钟，差点把运行错误当成击杀。

## 15. 用“能读/有片段”代替完整

- **症状**：`mutations.xml` 能打开、容错解析能读出 503 条，就按 503 条做统计。
- **真实**：文件 2,063,727 字节里有 1,622,016 个 NUL，首个在 417,792（102×4096）偏移；真实总数是 2528。文件系统写洞/并发写不会在读取时报错。
- **检查法**：四件套缺一不可——① 全文件 NUL 计数为 0；② 严格 XML 解析；③ 总数 == PIT 控制台 `Generated`；④ 各状态计数之和 == 总数。容错恢复结果只作诊断。
- **代价**：一次错误对比表；若没有总数校验，会把 20% 的样本当成全量。

## 16. 用目录 Allow ACL 代替有效写入

- **症状**：`icacls` 显示当前用户 `Modify`、全是 Allow，写入仍 `Access denied`，于是判断“目录被锁/软件 bug”。
- **真实**：进程运行在 **Low 完整性**（`whoami /groups` 的 `Mandatory Label` 为 S-1-16-4096），目标目录是 Medium；Windows 的完整性级别先于 ACL 生效。
- **检查法**：先看 Mandatory Label，再试写父目录与子目录作对比，最后才查 ACL；修复用 Medium 进程写入，或按需调整完整性标签（`icacls ... /setintegritylevel "(OI)(CI)Low"`，注意引号）。
- **代价**：约半小时误判，并一度准备去改 ACL（方向错误）。

## 17. 用相邻用例代替作用域与全局状态核对

- **症状**：复制隔壁测试的 helper、类名和断言；新增用例编译失败，或单跑绿、全量红。
- **真实**：`uniq()` 声明在另一个 `@Nested` 内，新容器看不到；`Mathematical_Expression.Options.useBigDecimal` 是静态全局，前一用例可改变它；把 `MaestroValidator` 的断言抄进 MaestroUK 的用例，直接测错类。
- **检查法**：复制后核对三样——helper 的**作用域**、被测**类名**、**静态开关**；依赖全局开关的断言用 `try/finally` 复位，或改用与开关无关的输入。编译失败先读错误行，不要猜。
- **代价**：本轮 3 次编译/运行返工（可见性 1 次、错误类名 1 次、全局精度 1 次）。

## 18. 用“合并版自述”代替变异身份对账

- **症状**：合并版报告写“剩余 27 条均等价/不可达、无提升空间”，据此收工或向下一条执行线传递。
- **真实**：同一变异身份在另一份同源报告里是 KILLED，`killingTest` 就在合并时被删掉的那个 `@Nested` 里。本轮 card 11 条（10 条来自 deepseek `CardProbeTests3`、1 条来自 GPT）、math 8 条（全部来自 deepseek `MathProbeTests`）都属于“用例被删，再写成等价”。
- **检查法**：`python -B scripts/mutation_union.py --provider A=... --provider B=... --baseline 合并版`；出现“别家杀、基线没杀”时，先回原套件取用例，不要接着证明等价。
- **代价**：若直接继承自述，card 少 11 个击杀（约 -0.8 个百分点）、math 少 8 个；更严重的是把错误结论传给后续执行线。

## 19. 用“报告百分比”代替合规审计

- **症状**：某套件在 `expression.engine` / `pricing.service` 明显更高，打算直接搬它的用例或骨架。
- **真实**：高出的部分正好对应 `mockStatic(DynamicFunctionCompiler)` 10 处 + `mockConstruction(ComplexExpression)` 1 处（GPT），以及连续 `thenReturn` 伪造 record 矛盾状态的 `stubbedRecord...` 2 处（glm）。它们让程序进入了原实现不可达的路径。
- **检查法**：先数 `mockStatic(`/`mockConstruction(`/连续 `thenReturn`，再定位命中包；命中区域的击杀不计入可借集合。只有能论证“没有替换被测实现”时才例外。
- **代价**：借进来可能踩赛题“违规示例二”，分数再高也可能被判无效。

## 20. 用“自动生成的注释”代替语义核对

- **症状**：为提升可读性，给 857 个测试方法批量生成 Given/When/Then。
- **真实**：类级描述取了类里第一个用例的 `@DisplayName`（方向错）；`@Nested` 与紧随的 `class` 各插一份（重复）；`map.put(...)`/`builder.add(...)` 被标成 `When`；纯断言用例 `When` 为空；脚本重跑再插一份（不幂等）。另有一次 PowerShell 参数 `$Output` 与内部变量 `$output` 同名（大小写不敏感），把 9,565 行文件写成 1 行。
- **检查法**：先跑三类样例（普通 / 纯断言 / builder），看首尾与行数；生成器要带“已注释则跳过”与作用域状态位；改写脚本先用小文件验证再上大文件；**注释改动必须早于最终 PIT**（会移动行号）。
- **代价**：一天里两次回滚重跑；注释没带来多少可读性收益，反而占用了提分时间。

## 21. 通用自检四问

下任何结论前问：

1. 这个数字是**本轮**构建产出的吗（哈希、时间、身份集对得上）？
2. 我说的是**下界、上界**还是**实测值**？
3. 有没有一个合法输入能推翻它？我试过吗？
4. 这条线的**合规上限**是多少？剩余项里有多少已经证明为等价/不可达？
