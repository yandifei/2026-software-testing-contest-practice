# 多执行者：隔离、冻结、集成

## 1. 分工依据

两题可以各有一个负责人；同题的大块零覆盖模块可按接口/状态边界拆分。小缺口先评估协调和完整重跑成本，不承诺“拆两半效率翻倍”，也不设所有机器通用的 10 个变异收益门槛。

主执行者持有完整模块清单、规则摘要和收尾时间。给每个代理明确：工作区、可改文件、禁止手段、负责模块、独立预期、验收命令、交付格式、截止点。每个模块有一个负责人，避免新模块无人认领而多个代理反复做旧题。

## 2. 写入所有权

```text
<workspace>/
  original/                 只读原题
  work/<problem>/           集成者唯一主测试与 target
  probes/<problem>/<owner>/ 各自测试、资源、target
  evidence/<run-id>/         冻结版本、报告、日志
  delivery/                 项目外 Java 与 ZIP
```

路径遵从用户，不写死 deepseek/GPT/用户名。同一主文件唯一写入者，同一 target 唯一构建写入者。副本不带旧 target；代理可在自己的副本构建，禁止共享 target 后靠先后覆盖“收敛”。

## 3. 冻结交付

交付必须包含：模块范围、文件路径与 SHA-256、原题基线、命令/退出码、实际发现测试数、原始报告位置、未解决点、是否含规则受限手段。文件交付后停止修改；修订发布新哈希并通知集成者，不能让集成者凭 mtime 猜“最新版”。

代理被用量/服务错误中断时：保存当前文件、已完成步骤、正在运行的构建 PID/命令/日志、剩余假设；主执行者核对后接管或缩小分工。不反复重试同一不可用代理，也不因代理结束就宣布任务完成。

## 4. 单文件合并

仅在题包允许嵌套测试时将独立段合入 `@Nested`；例如历史 Research 题包建议不用内部类，不能强制此模式。

- `@Nested` 隔离成员名称，**不完全隔离生命周期**：外层 BeforeEach/AfterEach 仍会影响内层。显式检查外层/内层钩子和静态状态。
- 自包含段不得依赖其临时副本里未交付的资源或工具类。匹配本项目 Surefire 配置，临时类名不匹配时显式选择；不添加别名类造成重复执行。
- 从冻结主文件 + 冻结片段幂等生成。脚本只能辅助文本处理，字符串、注释、text block、嵌套类都可能影响解析，不能称任一脚本天然正确。
- 并行补测优先"片段文件"而非"各自编辑主文件"：代理交付一段只含成员的文本（无 `package`/`import`/类声明），在自己 `cp -r` 的副本里粘贴、编译、跑定向 PIT 自证；集成者按固定顺序拼接后一次性真编译。片段契约要提前约定：方法名前缀、辅助方法前缀、不复用未交付资源、不新增依赖。拼接后先 `mvn test` 再全量 PIT，拼接期暴露的典型错误是 mock 返回类型不符、被注册对象构造非法、断言重载歧义。
- 先清点临时源文件，确认内容已合入后移出活动测试目录。只处理本轮拥有的副本，清理前验证绝对路径。干净构建防止旧 test-classes 进入 PIT。
- 重跑合并后的完整 JUnit、JaCoCo、PIT。局部成功不能替代合并结果，实际发现数不等于注解数之和。

## 5. 状态隔离与失败定位

注册表、缓存、单例的状态可能让 Surefire 与 PIT 得到不同结果。先确认可复现调用序列和顺序差异，优先使用真实初始化/清理 API；必要反射清理须符合白盒边界并在 finally 恢复。不要用“接受任意异常”消除失败。

集成失败将失败类、场景、完整日志位置和双方哈希回传；只替换明确的新修订段，再完整验证。源码里没有某测试类时查旧产物/发现配置，不能直接判定“幽灵类”后盲删。

## 6. 独立复核

集成者从冻结的原始报告重新统计，不采信代理自报。XML 严格完整、变异身份唯一、目标集合可比、构建正常结束、测试哈希相符后才用于验收。未覆盖、存活、超时、运行错误分别列；异常高分先查条件与来源，不改写原报告。

旧 Surefire 文件可残留；按本轮发现类集合统计，并清晰标出排除的陈旧文件。不能只挑绿色报告隐藏本轮失败。

## 7. 截止安排

根据实际构建时长留最终全量验证/验包/上传余量，截止后先交可核验结果。是否集成看预计收益、回退、合规与耗时，不只看用例数。正式提交版本的选择按用户要求、规则和真实得失说明，不能承诺“所有指标不退才有价值”，也不能隐瞒单项回退。

## 8. 跨版本与跨会话对账

可比较前提：生产源码/字节码、工具配置、目标与算子可对应；报告完整。键为：
`(mutatedClass, mutatedMethod, methodDescription, mutator, tuple(indexes))`。
先查缺字段、重复键、左右集合差；行号/description 不够唯一，killingTest 改名不代表变异改变。

列新增、保留、丢失以及全部状态迁移，再按模块聚合。“他杀我活”是研究线索，仍需审查输入、oracle、规则与状态依赖。对方也可能通过改变运行逻辑取得高分；未验证前不能移植或宣称可达。

杀死集合并集只是候选互补量，不是可实现上限：合并可能引入状态干扰或时间问题。用户要求独立重写时只能参考缺口定位，不能复制旧方法；允许复用时也需完整验证。
