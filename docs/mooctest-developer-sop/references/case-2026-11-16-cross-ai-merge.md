# 2026-11-16 复盘：三家 AI 同题套件的对比、择优与合并（相互借鉴线）

本文记录一次“只有测试文件不同、生产代码完全同源”的三方对比：拿到 `GPT/rewrite`、`deepseek`、`GLM` 三条执行线的成品测试后，如何在赛程尾段约 1 小时内选骨架、补边界、给出可核验的上限，并处理环境与报告故障。**数字是案例，不是上限；方法可迁移，结论不可直接搬。**

## 1. 条件与规模

| 项 | card-approval | math-assessment |
| --- | --- | --- |
| 生产代码 | 105 个 Java 文件，51 个类 | 136 个文件，68 个类 |
| 数据集 | 1320 变异 / 2013 分支 / 2364 行 | 2528 变异 / 2659 分支 / 4050 行 |
| 三份候选是否同源 | `src/main` 与 `pom.xml` 三方逐字节相同（SHA-256 一致） | 同左 |
| 构建 | JDK 21、Maven 3.9.11、JUnit 5.10.2、PIT 1.15.3 DEFAULTS | 同左 |

同源是移植的前提；目录名、文件大小、完成时间都不作判据（见 [套件移植](suite-porting.md) 第 1 节）。

## 3. 选型与借鉴（不是“拿来主义”）

1. **骨架按实测选**：card 选 deepseek（分支 99.30%、击杀 97%），不是行数最多的 GLM（815 例但击杀 55%）；math 选 deepseek（分支 98.35%、击杀 2422），不是分支略高（98.42%）但击杀只有 2106 的 GLM。
2. **只搬“对方独有且可解释”的用例**：
   - card：从 GLM 的 `cardFormat_maestro`、`cardFormat_verve`、19 位 Luhn 用例中提炼 7 条长度/IIN 边界，改写为独立 `@Nested`，修正其“6 位前缀直接断言 validate”的写法错误；
   - math：从 GLM 得到退款窗口等值点与排课周末/混合教室线索，补 3 + 2 条。
3. **搬之前先查“是否已有同线杀手”**：新增 5 条数学用例里，3 条退款等值点中只有 1 个 index 是真正新增击杀，其余与现有 `ResidualAttacks` 用例重叠；排课 2 条也被 `SurvivorKills`/`Scheduling` 覆盖。**先按 killingTest 名反查，再决定写不写**，否则只是重复劳动。

## 4. 途中问题与恢复（症状 → 原因 → 恢复 → 防止复发）

| 现象 | 原因 | 恢复 | 防止复发 |
| --- | --- | --- | --- |
| 三方报告数字对不上、目录报告缺失 | 报告早于测试最后修改（deepseek card 报告 15:10，测试 15:36）；GLM 的 `mutations.xml` 尾部截断，只恢复出 1017/1320 | 全部重跑 `clean test` + 全量 PIT，以本轮为准 | 报告 mtime ≥ 测试文件 mtime；严格解析且总数 == 控制台 `Generated`，否则不进对比表 |
| 分析过程中源文件仍在变 | 另一条执行线在 15:48 仍在改 `deepseek/math-assessment` 的测试 | 立即快照到工作区并冻结哈希，后续只读快照 | 开工先复制并 `Get-FileHash`，分析对象是快照，不是活动目录 |
| 写入 `相互借鉴` 被拒（Access denied），但 ACL 全是 Allow | 当前 shell 是 **Low 完整性**（`whoami /groups` 显示 S-1-16-4096），目标目录是 Medium；完整性级别优先于 ACL | 用 Medium/host 文件工具写入；后续会话切换为完全权限 | 先查 Mandatory Label 再查 ACL；`icacls /setintegritylevel "(OI)(CI)Low"` 注意引号，或避免跨完整性级别写 |
| `mutations.xml` 2,063,727 字节中 1,622,016 个 NUL，起始偏移 417,792（102×4096） | 并发写/中断留下的稀疏洞；`recover` 只能读出 503/2528 条 | 删掉重跑 PIT；单写者、单线程 | 严格解析前先扫 NUL；恢复模式结果只作诊断，绝不进交付表 |
| `-Dthreads=4` 跑出 23 个 RUN_ERROR，KILLED 2397；同文件单线程 0 个 RUN_ERROR、KILLED 2419 | PIT 并发分析下的 minion/静态状态抖动 | 正式报告改用单线程默认值 | 提分可以并行探索，**验收只认单线程独占运行** |
| 旧报告标“35 条等价”，其中至少 7 条可杀 | 旧结论没有覆盖“长度窗口等值点/奇数长度循环” | 对 12/19 位、Luhn 19 位等边界逐个补输入，35 → 27 | 继承的等价清单只当假设；先做值域边界复攻（等值点、±1、奇偶、空串） |
| 新增用例里把 `MaestroValidator` 写进 MaestroUK 的测试；`uniq()` 在另一个 `@Nested` 里不可见；复数精度受全局 `useBigDecimal` 影响 | 复制相邻用例时未核对类名、成员作用域、静态全局状态 | 编译错误即修正；去掉顺序敏感断言 | 复制后先读类名与 helper 作用域；涉及全局开关的断言必须 try/finally 复位，或改用不依赖开关的值 |

### 4.1 三家 AI 的矛盾点在哪里

| 来源 | 表面证据 | 矛盾/错误 | 以后怎么避免 |
| --- | --- | --- | --- |
| GLM | 815 个 card 用例、分支 99.16% | 变异击杀只有 55%：用例多但大量无断言/重复，分支覆盖掩盖了断言强度 | 选型同时看 KILLED 与 test strength；分支高击杀低 → 先抽查断言，再谈合并 |
| deepseek | 报告写“剩余 35 条全部等价” | 其中至少 7 条可被真实边界输入杀死；且报告时间早于测试最后修改 | 旧等价清单只当假设；报告 mtime 必须 ≥ 测试 mtime |
| GPT/rewrite | 引擎分支 95.94%、行 96.99% | card 只有 32 个用例、分支 89.27%：同一作者在不同题上的采样密度差 7 倍 | 按类/按包列缺口，不按整体百分比判断“够不够” |
| 三家共同 | 都有 `target/pit-reports` | 报告可能截断、缺失、含 NUL 或与测试不同版本；“有报告”不等于“有效报告” | 四件套：NUL=0、严格解析、总数==Generated、mtime 新鲜 |

结论：AI 产出的**测试代码**可以继承，**结论与报告**不能继承。继承前必须重跑；重跑后用集合而不是总数对账。

## 5. 剩余项与“上限”表述

- **card**：1293/1320（97.95%）。27 条剩余均有逐条证明，分四类：值域为空（`AdvancedLeavePolicy` 的 `(0,0.5)`、`OvertimePolicy` 的负分钟）、构造器不变量（`ExpensePolicy` 的 clientBillable/cap、`Shift` 的 NIGHT NPE）、重复扫描（`VerveValidator` 第二个 for）、代数等价（Luhn 取负不改变模 10）。分支 1999/2013，14 条缺口同样来自不可达。
- **math**：2423/2528（95.85%）。78 SURVIVED + 27 NO_COVERAGE + 4 TIMED_OUT；引擎 44+21 占大头，其余为 money 归一化、日期区间倒挂死区等。
- **表述纪律**：先算“合规可达上限”，再向用户承诺目标；100% 不可达时给出证明而不是找捷径。任何 mock 被测类、伪造构造器禁止状态、改写字节码换来的“击杀”都不能计入。

## 6. 可迁移 / 不可迁移

可迁移：
1. 同源 → 冻结 → 重跑 → 同口径三指标 → 选骨架 → 只搬独有用例 → 全量复核。
2. 报告新鲜度四件套：mtime、严格解析、总数、身份集。
3. 等价清单复攻顺序：等值点 → ±1 → 奇偶长度 → 空/空白/null → 构造器边界。
4. 环境故障先分层：进程状态 → 完整性级别 → ACL → 文件内容（NUL/截断）。
5. 上限先声明：不可达分支与等价变异先量化，避免“差 2% 就作弊”。

不可迁移：具体百分比、类名、PIT 耗时、本机完整性级别设置；换题必须重新计算分母与缺口。
