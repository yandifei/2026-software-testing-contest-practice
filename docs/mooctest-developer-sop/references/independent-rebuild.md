# 从原题重新设计测试的复核流程

适用：用户明确要求重新做题，或旧测试与原题版本不匹配、断言来源不可信。重做的目的应是发现旧设计遗漏和获得独立复核，不能保证程序里本来不可达的路径变得可达。

## 保留对照组，重新设计用例

- 在独立目录建立重做版本，按原题包的源码/POM 文件清单与 SHA-256 校验；不复制旧 target，不覆盖旧最好成绩版本。
- 根据源码公开接口、题目要求和可观察状态重新列场景。独立编写测试，不把旧文件换名后称为重做。
- 为每个复杂算法选择独立判定方法：动态规划用小规模子集枚举、Luhn 用固定数位映射和手算样例、随机模拟用受控序列、图算法用路径约束/小规模手工图。
- 当前实现违背需求时，把现状刻画与业务期望分开说明，保留缺陷复现；通过率不能作为业务正确性证明。
- 边界矩阵检查区间内部、两端与相邻非法值；状态测试同时检查返回、对象字段、外部关联与失败后未发生的改变。

## 用变异身份比较新旧版本

比较前先核对两轮生产源码/POM、原目标、算子和全部变异集合一致。单个变异以类、方法描述符、算子和指令 indexes 识别；blocks 可以作额外诊断，但不要用 killingTest 名称标识变异本身。

同一个变异从非 KILLED 变成 KILLED 才是新增检出；killingTest 换了名字或运行顺序改变不算提升。KILLED 变成 SURVIVED/NO_COVERAGE 是回退。新旧杀死数相等也可能同时发生收益与回退，应逐项列出。

如果生成集合不同，先解释编译、工具配置、目标或原码版本变化；禁止将这两个比例直接当同条件提分。分支、PIT 行覆盖和变异杀死各有口径，不相互替代。

## 只针对有证据的回退补测

新写测试往往先漏掉小但重要的条件：短路右侧、相等点、状态副作用、负零、解析失败。完整运行后，针对具体行/算子写出原版和变异版的结果差异，再增补一条可复现用例。每次最终修改都重新完整验证。

保留原版更优覆盖的证据，新版仅在确认没有回退且有实际收益时替换推荐版本。没有收益也保留重做结果及其检出的设计/业务问题，不伪造“重做成功所以满分”。

## 知识点和研究方向

1. **测试数量不是质量分数。** 一个参数矩阵可能展开许多执行用例，一个穷举性质测试也可能只计一个；比较应看检出的具体行为差异。
2. **副本分层。** 新容器不一定复制元素；返回 Map.Entry 等可变引用可能暴露内部对象。分别测试容器修改与元素修改是否影响原对象，先确认公开 API 的真实行为。
3. **独立收敛不等于形式证明。** 两套独立测试遇到同一存活项，可以增加复核可信度，但仍需路径条件、输入域和语义证明，不能据此直接判等价。
4. **变异集合是实验条件。** 同一分母不代表同一集合，必须检查集合差异；研究可比较变异身份稳定性、独立 oracle 的互补性、减少用例后的检出保持情况。
5. **可持续状态。** 用户目标未达成时明确保留 NOT_MET，并说明具体阻碍。保存阶段性成果、推送提交或更新技能不等于原目标达标。
