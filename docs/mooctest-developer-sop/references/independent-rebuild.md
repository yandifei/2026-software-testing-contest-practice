# 独立重写与回退对账

适用：用户明确“删掉之前重新写”，或旧测试来源/断言不可信。独立重写是设计约束，不保证指标自然提高。

## 1. 清空活动测试，保留可追溯对照

从原题包建立新工作副本，不带旧测试和 target；旧文件可作为备份放在活动项目/提交包之外。用户要求删除旧版本时不能继续把旧版本当默认交付，也不能不留说明地覆盖无关文件。

依据新题的全部模块、规范和可观察行为独立列矩阵并编写新测试。旧报告可指出“此模块缺失”，但复制旧方法、批量导入旧套件、只换名字均不叫独立重写。若用户后来允许复用，再将产物明确标为“合并增强版”，记录来源，不追认它为独立重写。

## 2. 公平比较

比较前固定源码/POM、编译器、插件、目标、算子与变异身份集合。身份：
`(mutatedClass, mutatedMethod, methodDescription, mutator, tuple(indexes))`。
行号、description、killingTest 是展示/诊断信息，不能替代身份。字段缺失或重复时停止自动对账。

严格 KILLED 集合比较：新增 = 新杀死 − 旧杀死；丢失 = 旧杀死 − 新杀死；保留 = 交集。总数更高仍可损失重要回归检出。集合不同则先解释条件差异，只对可匹配子集作明确限定的比较。

损坏的旧报告只能用于带警告的法证分析，不能标成通过的基准。分别列 METHOD、LINE、BRANCH 变化和未覆盖模块，不用测试数量评价质量。

## 3. 针对回退重新设计

逐个回退写出原/变异差异和新候选输入，独立实现补测。不是看到丢失就把旧方法贴回。合并后的新版本必须重新冻结和完整验证；旧版本的结果不能为它背书。

当截止前无法消除回退，交付实际新版及清单，并准确说明目标未完全达到；不把局部提高写成全面改进。选择提交版本遵循用户当前要求和可核验结果，不能擅自换回旧套件。

## 4. 本轮教训

2026-11-15 GPT Card 重写在相同变异集合上新增杀死 386、丢失 147，净增 239。GPT Math 的提升报告明载又并入旧 350 用例，故最终 506 用例产物应称合并增强版；其规则冲突另见 [GPT 复盘](case-2026-11-15-gpt-review.md)。
