# 防错手册：从证据到恢复

按遇到的问题查表，不要求每轮机械通读所有历史事故。通用流程是：保存原件→确定版本/范围→提出可检验原因→最小修正→验证恢复→记录仍未知的部分。

## 1. 任务与规则错误

| 症状 | 错误推断 | 正确恢复与验收 |
| --- | --- | --- |
| 旧题测试很多，新题仍低分 | 以为项目同名就覆盖充分 | 全包列清单并对源码差异，补零覆盖模块；每个模块有负责人及带断言用例 |
| 只看分支/变异 | 沿用旧权重；再强制方法优先 | 当前权重可取得则记录，未知不假设；四项独立报告，按缺口与边际收益决策 |
| 宣布独立重写却合入旧套件 | 用结果好替代用户约束 | 从空测试重新设计，旧文件放项目外；复用版明确改名“合并增强版” |
| 源码/POM 哈希未变便称合规 | 忽视运行时改变被测实现 | 审查 mock/反射具体行为，按 [白盒边界](whitebox-research.md) 判断 |
| 研究要求“必须试 MockedStatic”，规则却禁止 | 历史经验越写越多互相抵触 | 在冲突段落原位修正，不在末尾加一个相反提醒；当前规则优先 |
| 代理/技能越多越好 | 协调与加载替代实际工作 | 只加载当前决策相关资料，分配独立模块并检查交付，不以流程标签评价质量 |

## 2. 测试设计错误

**弱断言与兜底遮蔽。** 多个拒绝条件同时存在时，`allowed=false` 可能被别的规则维持。构造其他条件通过的单故障输入，断言完整理由/状态；同类型异常被下游顶替时，确认消息是否契约后精确断言。

**输入域遗漏。** 字符解析不能只想到 0–9/字母；核对实际 Character API 值域、前导零、解析溢出。数值包含阈值相等、±0、极值、中间溢出；每个反例先确认本题输入契约。有限枚举没找到不等于全域证明。

**把公开路径等价说成所有入口等价。** 记录每个结论的入口与不变量。私有方法若在许可范围可直接调用，应重新判断输入域；若必须伪造禁止状态才能区分，不能以此取消真实路径的限制说明。

**expected 写错后照实际输出改。** 先保留失败，核对重载、单位、舍入、手算、规范及独立参照；探针用于确认实际行为。修正预期必须有独立理由；实现确有缺陷则写刻画测试和缺陷说明，不吞异常。
本轮 GPT 曾把 3+4+5+6 误算为15，正确18有独立算术依据；这与把引擎异常输出直接当正确答案不同。

**工具语义靠记忆。** 变异名不能直接推出 Java 条件恒真/恒假；结合实际版本 mutator 和目标字节码。先做最小区分输入，不要求每个变异都昂贵反汇编。若语义仍不确定，记未解决，别归咎插桩。

**断言"缺依赖会失败"前先清注册表。** 全局函数/组件 map 未必被 `@BeforeEach` 清理；另一个用例先注册了该依赖，断言"应当抛异常"就会直接失效（2026-11-15 省赛实测：`avg` 依赖 `sum`，被别的用例注册后不再抛）。用真实 unregister API 显式清理，再断言异常类型与消息。

**返回值断言前读实现。** `getInstance(name)` 可能内部自动注册，使 `register(x, true)` 的 `containsValue` 命中而返回 `false`；方法名与返回值语义无关。注册/缓存类判定先看：谁写入、谁清理、判 `containsKey` 还是 `containsValue`。

**超时被当杀死。** KILLED 和 TIMED_OUT 分列。测试超时只检验应终止行为，宽裕且受控，不能用毫秒性能猜 mutant。PIT 超时计算和异步覆盖归属受版本/适配器/执行方式影响；testsRun=0 不足证明“只认主线程”，需最小复现和原日志。不要把历史 1 秒/3 秒当通用常量，也不要无限生成无法停止的后台线程。

## 3. 构建与报告错误

| 症状 | 查证顺序 | 恢复 |
| --- | --- | --- |
| java=21、Maven=8 | mvn -version、JAVA_HOME、实际可执行路径 | 当前进程设置本题 JDK，再验证，不改全局变量 |
| PIT 使用旧断言 | 测试哈希、编译时间/产物、POM 生命周期 | 冻结后先编译测试，完整验证 |
| XML 截断/拼接 | 构建是否结束、日志退出码、写入者、目标配置 | 保留原件，隔离副本重跑；诊断抽取不能正式计分 |
| 分母变化/高分突升 | 全量或局部目标、算子/编译器、身份集合 | 解释实验条件，不能只比总数或硬套历史分母 |
| clean 文件被锁 | 进程归属、打开文件、并发 target | 释放本轮拥有的锁或换干净副本；不默认绕过 clean |
| Surefire 有不存在的类/旧失败 | 本轮发现清单、旧 XML/class、继承/配置 | 归档旧证据，干净输出重建，不盲加全部 XML 计数 |
| JaCoCo 数据路径乱码/缺报告 | agent destfile、真实数据、同轮 class | 只有来源可证才恢复副本生成报告；未知则重跑，不借别轮 exec |
| 只有 HTML 首页 | 原 XML/数据、类页/资源、结束状态 | 首页存在不是完整报告，结构与运行来源都要验证 |
| 取消构建后报告仍在变 | 包装进程 vs 真实进程树、报告 mtime | 按项目目录匹配 `java`/mvn 进程（PIT 看 `multiModuleProjectDirectory`），确认归零再重跑；重跑前记录报告长度/哈希 |
| `mutations.xml` 出现 `<mutations partial="true">` 或标签错乱 | 是否有并发写入、构建是否正常结束、文件是否被截断 | 保留原件、隔离副本重跑；partial/截断只作诊断，不出正式比例 |
| `mutations.xml` 体积正常但含大量 NUL（实测 2,063,727 字节中 1,622,016 个 NUL，起始在 102×4096 偏移） | 是否中断过 PIT、是否有多个进程同写、文件系统是否留下写洞 | 保留原件并记录 NUL 数与偏移；删掉重跑，保持单写者、单线程；容错解析只作诊断，严格解析且总数 == 控制台 `Generated` 后才可用 |
| 报告 mtime 早于测试文件 mtime，或测试改动后报告未变 | 报告对应的测试哈希、构建结束时间 | 一律重跑；报告必须晚于最后一轮测试构建，且与测试文件哈希对应 |
| 统计结果为全空/全 0 | 解析器把子元素当属性、或取错层级 | 先做字段非空率自检（行号非空率、各状态计数之和 == 总数），再算指标 |
| 为释放文件锁而强杀正在写报告的 PIT | 锁持有者、报告字节数、ZIP 内报告的状态和 | 不要 kill：等它结束，或换干净副本重跑；已残缺的报告不得进交付包，也不得计入成绩，只能记事故 |
| 上传脚本名与 `public class` 名不一致（如 `card-approval-StudentTest.java` 里声明 `class StudentTest`） | 页面回执文件名、类声明 | 立即用 `类名.java` 重交（以最后一次为准）；冻结时就固定为 `类名.java`，上传前再比一次 |

归档诊断文件保留原字节，修复后的新构建另记 run-id。容错读取损坏报告只能说明“已恢复若干片段”，必须非成功状态且不输出可验收比例。不要以正则去重掩盖混合运行。

## 4. 并行与状态错误

- 主文件/target 单写入者；交付锁定哈希，后续修订另发版本。
- @Nested 不隔离外层钩子；合并前审查层级、静态缓存、注册表，合并后全量实测。
- 合并脚本若只数花括号，会被字符串/注释/text block 误导；脚本成功不等于 Java 有效。
- 临时 probe 已合入时移出活动测试目录，干净构建移除旧 class；不能让独立副本和嵌套版重复执行。
- Surefire 绿而 PIT 基础套件红，先复现顺序/状态差异；使用有效清理与恢复，禁止 catch 任意异常使测试“通过”。
- 外部覆盖工作文件时先查内容哈希、快照和写入者；在关键修改、交付与每轮构建边界保存快照。不强制所有项目启动 20 秒永久守护。
- **完整性级别优先于 ACL**：Access denied 但 ACL 全 Allow 时，先 `whoami /groups` 看 `Mandatory Label`；Low 进程写不了 Medium 目录。修复用 Medium/宿主进程写入，或按需设置目录完整性标签（命令里的 `(OI)(CI)` 要加引号）。
- **同一工作区可能有别的执行线在写**：本轮 `deepseek/math-assessment` 的测试文件在分析期间仍被修改（15:48），任何“当前最强套件”的结论都必须基于冻结快照的哈希，不基于活动目录。
- **PIT 并发会制造假状态**：同一测试文件用 `-Dthreads=4` 出现 23 个 `RUN_ERROR`，单线程为 0。并行只用于探索，正式验收用单线程独占，并分列 KILLED/RUN_ERROR/TIMED_OUT。
- **只改注释也会让报告行号漂移**：注释插入会移动后续源码行号，PIT 报告里的行号引用随之失效。冻结顺序应是“先定稿注释与命名，再跑最终 PIT”；若已跑完再改，需重跑或明确不再引用行号。
- 子代理报用量上限时保存成果与断点，主执行者接管；重试没有新条件时不会自动解决。
- 并行补测用"片段文件 + 副本验证"：代理只写独立片段文本（不含 `package`/`import`/类声明），各自在 `cp -r` 的副本里编译并跑定向 PIT；主执行者负责拼接、一次性真编译与全量复核。多人直接编辑同一主文件不在"合并后重新运行"的覆盖范围内。
- 拼接后必查三类编译/运行错误：mock 返回类型与声明不符（如返回 `PackExpression` 却 mock `NameExpression`）、被注册对象构造非法（函数名只允许字母）、断言重载歧义（`assertEquals(2, Integer)` 改 `intValue()`）。先 `mvn test`，不要直接跑 PIT。
- **生成式改写（注释/重命名/格式化）要幂等、作用域感知、样例自验**：批量脚本先在三类样例（普通 / 纯断言 / builder）上跑，核对首尾与行数；重跑不得重复插入；`@Nested` 与 `class` 只能各写一次文档。PowerShell 变量大小写不敏感，`param($Output)` 与内部 `$output` 重名会被静默覆盖（本轮把 9,565 行写成 1 行）。
- **注释改动会移动行号**，必须在最终全量 PIT 之前定稿；跑完再改，报告里的行号引用全部失效。

## 5. 上传与表述错误

同名同大小不等于同内容；页面“已提交2/2”不证明上传者或当前 Java。按 [评分与回执](scoring-and-submission.md) 保存本次操作证据。来源不明的新提交先辨明，不争抢最后一次提交。

“当前本地产物”“完整构建验证”“合规候选”“平台已接受”“平台已出分”是不同状态，不能跳级表述。其他工作区高分是对照证据，不是本会话结果；损坏归档中提取出的数字也不能与有效报告混表不加说明。

## 6. 本技能的回归场景

每次修订核心流程至少核对：

1. 只要求复盘：不得继续改比赛测试或重交。
2. 权重取不到：标未知，推进有断言的模块测试，不默认25%。
3. 禁止改变运行逻辑但 POM 有 Mockito：不得把 mock record/enum 当例外。
4. 用户要求重写：旧用例不能自动合并；探针输出不是独立预期。
5. 测试刚改而 XML 截断：报告无效，保留原件，干净验证后才称提升。
6. 新旧杀死数相同但身份互换：列一项新增、一项丢失，不说“完全无变化”。
7. 已授权提交但出现不明新版本：核对来源/收尾安排，不抢提交。
8. ZIP 内 Java 与独立 Java 同大小不同字节：验包必须失败。
9. 手上有两份同题测试：先比 `src/main` 与 `pom.xml` 哈希，再决定移植；只搬"更大/更完整"的那份不算依据。
10. 取消后台构建：确认真实进程已退出、报告 mtime ≥ 最后一次构建，才可解析。
11. 统计脚本输出全空或全 0：先查字段非空率与层级，修解析器，不得把结果当"零缺口"。
12. 手上有三份以上同题套件：先冻结、再各自重跑；旧报告不得直接进对比表（见 [三方合并案例](case-2026-11-16-cross-ai-merge.md)）。
13. 报告 XML 含 NUL 或截断：严格解析 + 总数 == 控制台 `Generated` + 状态和 == 总数，缺一拒收。
14. 继承上一轮的"等价清单"：先做边界复攻（等值点、±1、长度上下界、奇偶），给不出反例才保留；本轮 35 条中至少 7 条被真实输入杀死。
15. 手上有合并版与其它同源报告的 XML：先跑 `scripts/mutation_union.py --baseline 合并版` 对账 `killingTest`；出现"别家杀、基线没杀"先回原套件取用例，不要接着证等价（本轮 card 11 条、math 8 条）。
16. 借任何高分套件前先数 `mockStatic`/`mockConstruction`/连续 `thenReturn`；命中区域的击杀不计入可借集合。
17. 上传前两查：文件名 == `public class` 名；ZIP 内测试文件与上传脚本 SHA-256 一致。
18. 打包期间 PIT 仍在写报告：等它结束；强杀产生的残缺报告不得入包、不得计入成绩，只能记为事故并说明 `.java` 才是计分主体。
