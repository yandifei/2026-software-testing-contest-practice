# 浏览器提交

登录、进入比赛列表和下载题包的前置流程见 [登录、选赛与下载](browser-entry.md)。提交阶段优先复用前面确认过的比赛页，登录失效时再按该流程恢复。

用户要求将指定题目材料提交到对应比赛时才上传和提交；只要求准备材料时停在本地验收。已有具体授权不重复询问。遵循当前工具对登录、验证码及最终确认的要求。

使用当前环境提供的浏览器控制能力，先读其操作及上传文档。有适用平台连接器则优先，否则用可访问性树、DOM 或截图操作，不要求固定插件或某种 API。

1. 复用用户指定或已打开的比赛页；没有页面时按用户赛事链接或平台比赛列表进入，不默认固定 contest ID。
2. 读取当前状态，核对平台域名、预期参赛账号、赛事标题、阶段、截止时间与题目工程，不把账号信息写入公共技能。
3. 核对上传槽、类型和容量。页面与打包依据冲突时先解决差异，不试投到其他题目。
4. 读工具上传说明，将交付记录的相对位置解析为工具需要的路径。分别选择同题已验收的 Java、ZIP；选择文件可能立即上传，应已有相应授权。
5. 动作后刷新状态，确认两个文件名、版本、上传结果和错误提示；无误后操作该题提交按钮，不复用旧控件 ID。
6. 获取成功提示、已提交状态或提交记录/时间，保存回执截图和文字至交付目录。工具支持时向用户展示截图。
7. 未出分则报告提交成功、评分中；平台成绩与本地指标分开记录。

登录或验证码障碍按工具要求处理，不绕过。超时先查提交记录，确认未成功才重试；一次恢复仍失败则停止并报告页面状态。重交前重新验证和打包，更新同版本两个附件，遵守当场重交次数和期限。

浏览器能力不可用时完成本地交付，说明需要用户操作的步骤。生成包、选中文件、上传、提交回执、评分完成分别验收，不把中间状态描述为成功。
