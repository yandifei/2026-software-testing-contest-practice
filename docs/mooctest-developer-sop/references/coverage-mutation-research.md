# 高覆盖率与变异测试：缺口驱动研究

适用：已有测试需要提分、指标接近 100%、用户要求全部覆盖/杀死，或历史报告宣称“已达上限”。先读取本轮原始报告与对应源码，历史结论只作为待检验假设。

## 1. 用证据决定下一轮测试

建立一张缺口台账：源码哈希、类、方法描述符、行号、PIT mutator/indexes/blocks、原表达式、变异表达式、可达前提、预期可观察差异、候选输入、验证结果。

- JaCoCo 未覆盖分支：先推导路径条件；能满足则构造输入，不能满足则给出路径矛盾。
- PIT NO_COVERAGE：先让该指令被执行，再谈断言；不要把未覆盖自动分类成等价。
- PIT SURVIVED：按“可达 → 状态产生差异 → 差异传播到可观察结果 → 断言检测”逐层分析。覆盖了分支，不代表覆盖了区分变异的输入。
- 同一行可以有多个变异，不能只按类名和行号合并；保留 XML 中的索引与块号。
- 单轮补测前写一句“若 X 被改为 Y，本输入会使结果 A 变成 B”。没有可执行假设就继续推理，不盲目追加大量样例。

对正常输入、非法输入、边界、异常类型/消息、返回集合副本、顺序和状态变化分别选择独立预期。复杂算法可用小规模穷举参照；不要用被测实现同时生成 expected。

## 2. 100% 的可达性与观察范围

先声明输入域和观察范围，例如公开 API 可构造的状态、返回值/异常/公开副作用。分开记录：

| 分类 | 要求的证据 | 后续动作 |
| --- | --- | --- |
| 可区分 | 有合法可执行输入和确定结果差异 | 增补测试，以 PIT 本轮 KILLED 验证 |
| 不可达 | 所有进入路径的条件互相矛盾 | 写路径证明，保留 JaCoCo 分母 |
| 等价 | 在声明输入域内可证明观察结果相同 | 写语义证明，保留 PIT 分母 |
| 接口不可观察 | 内部值不同，但公开结果不依赖该值 | 写数据流证据，勿称所有观察方式下都等价 |
| 环境/状态受限 | 依赖私有状态、时钟、资源极限或尚未明确的许可 | 单列限制，不冒充等价 |
| 未解决 | 尚未找到反例或完成证明 | 如实保留，不宣称已达到理论上界 |

边界变异 `<`→`<=` 常在等号处赋回相同值，但证明必须覆盖浮点负零、NaN、溢出及后续操作；不能把“看起来一样”当证明。重复逻辑也可能通过另一条路径补偿第一条路径的删除。是否等价取决于两段逻辑读取的输入在期间是否改变。

一个确定不可达分支或确定等价变异就足以说明原始 100% 不可实现。由此只能推导相应上界；只有其余全部可区分项已经杀死，才能说达到了该上界。不可把“已分析完缺口”重新命名为“100% 变异杀死率”。

## 3. 反驳“被掩盖所以等价”：有限输入也会产生无穷大

Research 的真实反例（2026-10-31 验证）：

```java
Budget budget = new Budget();
budget.add(new Budget.Item("a", Double.MAX_VALUE, 1, "lab"));
budget.add(new Budget.Item("b", Double.MAX_VALUE, 1, "lab"));
budget.setReserveRatio(-0.25);
assertTrue(Double.isNaN(budget.requiredReserve()));
```

判定链：两个有限非负成本之和溢出为 `+Infinity`。原实现将负比例裁剪成 `+0.0`，乘积为 NaN；`NaN < 1000` 为 false，返回 NaN。删除负比例裁剪后，乘积是 `-Infinity`，被最低值分支变为 1000。输入不需要反射，预期由 IEEE-754 运算规则独立得到。

这刻画题包接受有限大值后发生的实际行为，不代表 NaN 是理想业务需求。若新题明确限制成本范围，需在允许域内重新评估，不能照搬该反例。

可复用检查矩阵：`+0.0/-0.0`、最小非零值、阈值左右邻值、最大有限值、多值累加溢出，以及中间值的无穷大/NaN。优先寻找合法有限输入构成的中间异常值；仅在 API 接受时直接传 NaN/Infinity。

重要区别：`+Infinity * -0.0` 与 `+Infinity * +0.0` 均为 NaN，因此这个反例只杀删除负比例裁剪的变异，不能据此声称也杀了负零边界变异。

## 4. 控制流与算术证明模板

### 重复扫描

若第 1、2 次扫描都比较同一局部整数 `x` 与同一个闭区间，且第一次命中即 return，则到第二次时 `x` 必不在区间内。第二次命中分支不可达；删除一次扫描可能由另一次扫描补偿。先验证变量没有在两次扫描间变化，也没有可观察的副作用，再判等价。

### 赋值后立即退出

若循环入口变量初始为 null，所有给它非 null 值的路径都立即 break，循环条件的非 null 出口不可达。到达后面的 null 检查时也可能已经确定恒为 null。用路径条件解释缺口，不尝试通过并发/反射改变局部变量来制造覆盖。

### 模运算与有符号溢出

证明“累加改累减是否保持整除判定”必须按 Java int 的模 2^32 运算分析。只有当整个累积结果是原结果的加法逆元时，才能使用 `s % 10 == 0` 与 `(-s) % 10 == 0` 的等价性。另检查 `Integer.MIN_VALUE`：取负仍是自身，两边整除真假相同。不要泛化为任意单项 `+`→`-` 都等价。

### 不可观察字段

某字段被更新但从不参与任何公开输出，则更改更新算子可能对公开接口不可观察。只读反射可扩大观察范围，但要先核对适用规则，且仍不能杀死真正赋回相同值的变异。缺口压力不构成改写私有状态、绕过不变量的理由。

## 5. 实测和交付口径

- 先固定原题包源码/POM 基线、测试版本和原插件目标/算子；保证新增和删除文件也会被基线检查发现。
- 分支率为 JaCoCo `covered/(covered+missed)`；杀死率为 PIT `KILLED/全部变异`。NO_COVERAGE、TIMED_OUT、RUN_ERROR 等各自保留，不全部归为断言杀死。
- 不在构建写入报告时读取并做最终判断；不完整 XML 先核对正在运行的进程/日志，等构建退出后再解析，不把半成品误判成报告故障。
- 使用本轮 clean 运行排除旧 class/report；检查 Surefire 发现数 > 0、失败/错误/跳过、最新报告、源码/测试及报告哈希。文件修改时间只是过期检查线索，不是版本对应的充分证明。
- 环境参数只处理已知构建问题，不改变覆盖目标、排除类或变异算子。保留实际命令、退出码、日志路径和失败尝试。
- 打包脚本从自身或参数解析根目录，日期取用户时区或显式指定；不要把固定盘符、旧日期、旧 Java 版本或“官方基线已核验”写成无证据的永久断言。
- 独立 Java 与 ZIP 内文件字节一致，ZIP 含本轮 target；记录源码/POM 基线、测试与原始报告的哈希。技能压缩包另行生成，禁止把 ZIP 自己包含进去。
- 有明确新反例才追加执行；已证等价/不可达且测试未改变时，停止无意义空跑。若用户仍要求 100%，报告无法满足的具体条件与已经实现的提升。

## 6. 可继续研究的问题（尚非已验证结论）

1. 自动路径条件提取能否把未覆盖分支区分为矛盾路径、状态约束和缺输入？需要用人工证明或可复现反例校验分类。
2. 如何在语义证明中统一处理 IEEE-754、Java 整数溢出和集合可达不变量？可用小规模枚举查反例，但有限枚举不能自动充当全域证明。
3. 怎样用公开调用序列区分时钟与私有计数器组合的 ID 算法变异，同时容忍时钟回拨、调度延迟和跨平台环境？未解决前不引入脆弱时间阈值。
4. 如何建立可机器核验的“题包→测试→构建→报告→交付包”来源记录，避免仅靠时间戳或历史百分比？优先保存内容哈希与一次构建的完整记录。
5. 测试契约若允许子类、可变集合、NaN 等特殊输入，哪些等价结论会失效？证明必须写输入域及观察范围，不把单题结论固化成通用规则。
