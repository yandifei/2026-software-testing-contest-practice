## 建议训练流程

1. **建立基线**：先读取 `pom.xml`、包名、测试入口和允许修改的范围，运行原工程，记录基线异常。
2. **列行为表**：每个方法记录正常输入、边界、空值、异常、返回值及状态改变；只选择对该 API 有意义的输入类别。
3. **写独立断言**：根据需求确定预期结果，检查返回值、内容、顺序、身份、异常类型等适用行为，不只写“不抛异常”。
4. **查覆盖缺口**：用 JaCoCo 找到没有执行的分支；覆盖率高只能证明执行到，不能证明断言能识别错误。
5. **查断言缺口**：用 PIT 分析存活变异，区分缺少断言、未覆盖和无可观察行为差异；不为提高比例删除困难目标。
6. **做可重复性检查**：恢复静态状态、资源与临时配置，避免随机数据、当前时间和测试顺序依赖。
7. **做一次完整交付演练**：从题包重新放入测试，运行，再按平台要求上传并确认最终版本。

练习记录建议包含“输入—预期—测试名—覆盖缺口—变异状态—修正原因”，这些是自用字段，不是官方提交模板。
