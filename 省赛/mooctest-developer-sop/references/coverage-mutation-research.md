# 高覆盖率与变异测试：缺口驱动研究

适用：已有测试需要提分、指标接近 100%、用户要求全部覆盖/杀死，或历史报告宣称“已达上限”。先读取本轮原始报告与对应源码，历史结论只作为待检验假设。

## 1. 用证据决定下一轮测试

建立一张缺口台账：源码哈希、类、方法描述符、行号、PIT mutator/indexes/blocks、原表达式、变异表达式、可达前提、预期可观察差异、候选输入、验证结果。

- JaCoCo 未覆盖分支：先推导路径条件；能满足则构造输入，不能满足则给出路径矛盾。
- PIT NO_COVERAGE：先让该指令被执行，再谈断言；不要把未覆盖自动分类成等价。
- PIT SURVIVED：按“可达 → 状态产生差异 → 差异传播到可观察结果 → 断言检测”逐层分析。覆盖了分支，不代表覆盖了区分变异的输入。
- 同一行可以有多个变异，不能只按类名和行号合并；保留 XML 中的索引与块号。
- 单轮补测前写一句“若 X 被改为 Y，本输入会使结果 A 变成 B”。没有可执行假设就继续推理，不盲目追加大量样例。

对正常输入、非法输入、边界、异常类型/消息、返回集合副本、顺序和状态变化分别选择独立预期。复杂算法可用小规模穷举参照；不要用被测实现同时生成 expected。

## 2. 100% 的可达性与观察范围

先声明输入域和观察范围，例如公开 API 可构造的状态、返回值/异常/公开副作用。分开记录：

| 分类 | 要求的证据 | 后续动作 |
| --- | --- | --- |
| 可区分 | 有合法可执行输入和确定结果差异 | 增补测试，以 PIT 本轮 KILLED 验证 |
| 不可达 | 所有进入路径的条件互相矛盾 | 写路径证明，保留 JaCoCo 分母 |
| 等价 | 在声明输入域内可证明观察结果相同 | 写语义证明，保留 PIT 分母 |
| 接口不可观察 | 内部值不同，但公开结果不依赖该值 | 写数据流证据，勿称所有观察方式下都等价 |
| 环境/状态受限 | 依赖私有状态、时钟、资源极限或尚未明确的许可 | 单列限制，不冒充等价 |
| 未解决 | 尚未找到反例或完成证明 | 如实保留，不宣称已达到理论上界 |

边界变异 `<`→`<=` 常在等号处赋回相同值，但证明必须覆盖浮点负零、NaN、溢出及后续操作；不能把“看起来一样”当证明。重复逻辑也可能通过另一条路径补偿第一条路径的删除。是否等价取决于两段逻辑读取的输入在期间是否改变。

一个确定不可达分支或确定等价变异就足以说明原始 100% 不可实现。由此只能推导相应上界；只有其余全部可区分项已经杀死，才能说达到了该上界。不可把“已分析完缺口”重新命名为“100% 变异杀死率”。

## 3. 反驳“被掩盖所以等价”：有限输入也会产生无穷大

Research 的真实反例（2026-10-31 验证）：

```java
Budget budget = new Budget();
budget.add(new Budget.Item("a", Double.MAX_VALUE, 1, "lab"));
budget.add(new Budget.Item("b", Double.MAX_VALUE, 1, "lab"));
budget.setReserveRatio(-0.25);
assertTrue(Double.isNaN(budget.requiredReserve()));
```

判定链：两个有限非负成本之和溢出为 `+Infinity`。原实现将负比例裁剪成 `+0.0`，乘积为 NaN；`NaN < 1000` 为 false，返回 NaN。删除负比例裁剪后，乘积是 `-Infinity`，被最低值分支变为 1000。输入不需要反射，预期由 IEEE-754 运算规则独立得到。

这刻画题包接受有限大值后发生的实际行为，不代表 NaN 是理想业务需求。若新题明确限制成本范围，需在允许域内重新评估，不能照搬该反例。

可复用检查矩阵：`+0.0/-0.0`、最小非零值、阈值左右邻值、最大有限值、多值累加溢出，以及中间值的无穷大/NaN。优先寻找合法有限输入构成的中间异常值；仅在 API 接受时直接传 NaN/Infinity。

重要区别：`+Infinity * -0.0` 与 `+Infinity * +0.0` 均为 NaN，因此这个反例只杀删除负比例裁剪的变异，不能据此声称也杀了负零边界变异。

## 4. 控制流与算术证明模板

### 重复扫描

若第 1、2 次扫描都比较同一局部整数 `x` 与同一个闭区间，且第一次命中即 return，则到第二次时 `x` 必不在区间内。第二次命中分支不可达；删除一次扫描可能由另一次扫描补偿。先验证变量没有在两次扫描间变化，也没有可观察的副作用，再判等价。

### 赋值后立即退出

若循环入口变量初始为 null，所有给它非 null 值的路径都立即 break，循环条件的非 null 出口不可达。到达后面的 null 检查时也可能已经确定恒为 null。用路径条件解释缺口，不尝试通过并发/反射改变局部变量来制造覆盖。

### 模运算与有符号溢出

证明“累加改累减是否保持整除判定”必须按 Java int 的模 2^32 运算分析。只有当整个累积结果是原结果的加法逆元时，才能使用 `s % 10 == 0` 与 `(-s) % 10 == 0` 的等价性。另检查 `Integer.MIN_VALUE`：取负仍是自身，两边整除真假相同。不要泛化为任意单项 `+`→`-` 都等价。

### 不可观察字段

某字段被更新但从不参与任何公开输出，则更改更新算子可能对公开接口不可观察。只读反射可扩大观察范围，但要先核对适用规则，且仍不能杀死真正赋回相同值的变异。缺口压力不构成改写私有状态、绕过不变量的理由。

## 8. 可达性攻击：输入值域扩展与遮蔽者拒绝（2026-11-01，corporate-card-expense-approval 实测）

### 8.1 变异语义先行

分析任何存活变异前，先从本地 pitest jar 反汇编 mutator 本体，确认语义再推理。RemoveConditionalMutator 的四种变体：

- `EQUAL_IF`/`ORDER_IF`：**移除**条件跳转（操作数先 pop/pop2）→ 控制流直落 → 条件恒真。
- `EQUAL_ELSE`/`ORDER_ELSE`：把条件跳转替换为**无条件 GOTO**（操作数先 pop/pop2）→ 恒跳转 → 条件恒假。
- 条件跳转字节码有两种方向（`if_acmpeq` 跳当相等、`if_acmpne` 跳当不等），同一变异名在不同结构上表现为恒真或恒假，必须结合被变异指令的具体 opcode 判断。

本次教训：曾按“恒假”推理 EQUAL_ELSE 而把可杀变异判死；曾手工 patch 字节码忘了 pop 操作数导致 VerifyError。手工模拟变异时必须同步 pop 操作数并保持代码长度/栈帧一致。

### 8.2 前置校验器遮蔽的逐层突破

TypeChecker 的固定检查顺序使靠后卡类型被更早校验器遮蔽。按值域逐层扩展输入，每层都能打开一批“不可达”：

1. **字母数位（10-35）**：目标校验器查短前缀（如银联 2 位 "62"），遮蔽者查长前缀（Maestro 6 位）。在目标前缀后放一个字母，遮蔽者的解析变成 7 位数（"6210000"=6,210,000）落出六位区间 [600000,699999]。
2. **Unicode 数字字符无 35 上限**：`Character.getNumericValue` 对埃塞俄比亚数字等返回 40/50/60/…（如 `፵`=40）。目标校验器需要 7 位精确值、遮蔽者查 6 位时，用"前导零 + 多位数"错开两者：`"060547፵"` 的前 7 个值拼成 "06054740"=6054740 精确命中 NPS 区间，而 Maestro 前 6 个值拼成 "060547"=60547 落空；`"03571B"`(B=11) 前 6 个值拼成 "0357111"=357111 命中 LankaPay，而 JCB 前 4 个值 "0357"=357 落空。
3. **前导零错位**：目标解析多位含前导零，遮蔽者解析更少位也含前导零 → 两值域错开。核心口诀：让"遮蔽者的解析成功且落空"，同时"目标的解析精确命中"。
4. **溢出边界**：多字母会让 6 值解析超过 10 位 → `Integer.parseInt` 抛 NumberFormatException 提前终止链；正常路径上所有遮蔽者必须**解析成功**，所以单字母（7 位解析）安全、多字母危险。被变异路径抛异常同样算测试失败，可用来杀变异。

### 8.3 遮蔽者拒绝法（白盒 mockConstruction）

真实输入确实不可达的遮蔽 return（如 DinersClub 54/55 与 MC 检查同一前两位解析、Verve 506xxx 恒在 Maestro 区间内），可用 Mockito 的构造器 mock 让遮蔽者"拒绝"：

```java
try (MockedConstruction<MasterCardValidator> ignored =
        Mockito.mockConstruction(MasterCardValidator.class)) {
    assertEquals(CreditCardType.DINERS_CLUB, TypeChecker.checkType("5400000000000000"));
}
```

mock 的 validate() 默认返回 false，链走到被遮蔽 return → EQUAL_ELSE 与 NullReturn 变异均可杀、分支可覆盖。注意口径区分：这是"mock 环境可达"，与"真实输入可达"是两类证据；报告分别标注。官方参考材料（组织方缺口说明文档）认可该做法并计入 791/801，证明其未违反"仅修改测试代码"的规则边界。禁止的仍是：运行时替换被测类字节码、探测 PIT mutant 身份后人为失败、改 POM 缩分母、篡改报告。

### 8.4 两类"看似被杀实则被顶包"的存活

- **下游异常顶包**：被变异跳过的检查，其异常由下游构造器以同类型抛出（如 withdraw 的过去时间检查被 WorkflowSnapshot 构造器 "updatedAt must not be before createdAt" 顶包）。修复：断言异常消息原文。
- **兜底逻辑顶包**：REJECT 短路被 `canStillSucceed` 兜底出相同终态。修复：构造"剩余票足以成功"的场景（ANY_ONE+多审批人+一人 REJECT）。
- **构造器不变量死分支**：Mockito mock record 绕过构造器（billable+空成本中心、MEAL+人数），mock 枚举常量构造不存在的状态（ensureActive 非活跃检查）→ 分支与变异均可触达。

### 8.5 本轮实测校准（2026-11-01）

corporate-card-expense-approval：真实输入层（字母+Unicode+下游消息+mock record/mock 枚举）达到 KILLED 787/801、分支 1175/1180；再加 mockConstruction（遮蔽者拒绝）达到 **KILLED 791/801、分支 1177/1180**，与官方参考缺口文档一致。最终残余 10 个变异点（ExpensePolicy L221/L222 cap 恒正、Luhn L76 取负模 10 等价、Verve L53-L62 重复循环互蔽）与 3 个分支方向有完整路径证明，是原始分母下的理论残留。证明模板：逐项写"被变异指令的 opcode → 变异后控制流 → 全体输入的值域分析（含全部 getNumericValue 值域）→ 下游异常兜底"。

## 9. 数学题实测攻击手册（2026-11-01，online-math-expression-grading）

官方参考缺口文档口径：**分支 1071/1072（最后 1 支为枚举 switch default，仅伪造 ordinal 可触达）、PIT 严格杀死率 984/992，TIMED_OUT 为 0，分母含全部变异、分子只计 KILLED**。从 895/992 追到该水平需要以下全部攻击面，每个都是"真实字节码执行 + 真实断言"，无一靠改报告或缩分母。

### 9.1 对象同一性断言（值相等 ≠ 对象相等）

边界变异在等号处"赋回相同值"，但变异路径常**新分配对象**（如 `ZERO.multiply(0.80)` 得到新 "0.0000"），而原件复用静态常量；`money()` 的 `setScale(2)` 对已是 scale-2 的对象返回 `this` 本身，于是身份差异完整传播到返回值。用 `assertSame(base, rescaled)` / `assertNotSame(maximum, capped)` 击杀 scoreAnswer 的 L151/L154/L157 边界、scoreMultipleChoice L200。先画 money()/formatStr 等归一化层：归一化**之前**的私有返回值的 scale/toString 仍是可观察面（直调 scoreEssay 断言 `"0.00"` 的 toString，变异体为 "0.00000"）。

### 9.2 record 构造态的非法值域（validate 只拦公开路径）

私有评分方法没有 validate 前置，record 全参数空间都是输入：

- `passedTests=4, totalTests=2` → passRate 2.0 → score=2×maximum → 触发 clamp true 边（L154），并杀死其 ORDER_ELSE。
- `rubricPercent=125` → essay 超额分同样触发 clamp。
- `completionPercent=Integer.MAX_VALUE` → ARTICLE 三元 else 分支 `weight×completion/100` int 溢出为 -10 → 0，与 true 分支 weight 不同（assessLesson L147）。
- 下降区间 `[1e300,-1e300]` → formatStr 容量 `(int)(len×|end−start|)+1` 饱和后 +1 回绕为 MIN_VALUE → `new StringBuilder(负)` 抛 NegativeArraySizeException；变异体 `end+start=0` 容量为 1 不抛 → 断言异常即杀（L95）。

### 9.3 MockedStatic：让"必抛异常"的 return 分支可达

BooleanCalculation2 的 null 操作数分支调用 `NumberUtils.ComparisonOperation` 恒抛 AbnormalOperation，两个 return 语句（L75/L81）看似不可达。用 `Mockito.mockStatic(NumberUtils.class)` 桩掉静态比较后，return 真正执行：NO_COVERAGE 清零，L74 三元（null 映射 0/1）与两个 null-return 变异全部可杀。口径："mock 环境可达"，报告与真实输入可达分开标注。

### 9.4 反射直调私有入口，绕开上游归一化

"公开路径上冗余"的调用在私有入口下可区分：`ArithmeticExpression.atom("  12.50")` 直调时 skipSpaces 删除立刻现形（unary 入口在公开链上预先消费了空白才让它看似冗余）。同一方法：直调 `unary("-5")` 杀 take('-') 删除；直调 atom 无数字输入断言 IAE 消息杀 `start==position` 删除。判等价前对每个私有方法的**每个入口**分别做攻击。

### 9.5 线程超时包装死循环变异（两个机制坑）

死循环变异（`start += step` 改减法、`start==end` 提前返回被删）用 daemon 线程 + `task.get(1s)` 包装，超时抛 AssertionError → KILLED。两个坑：①等待上限必须 < PIT 默认 timeoutConstant（3000ms），否则 PIT 的超时先触发记 TIMED_OUT；②PIT 的覆盖归属只认**测试主线程**，daemon 线程执行的指令 testsRun=0 → 该变异无测试可跑。因此每个循环的条件行与自增行都要保留至少一个主线程执行的测试（自增指令若只在包装线程内执行，变异永远 TIMED_OUT，如实记录为工具行为）。

### 9.6 静态状态隔离与 PIT fork 复用

单例 getInstance 的新注册路径（fresh-path）null-return 变异在复用 fork 中不可观测（前序变异运行已注册所有名字，后续测试全走缓存路径）。`@BeforeEach` 反射清空静态注册表（标准测试隔离）后，每个测试都真实走新注册路径 → 3 个 null-return 全杀。共享静态状态类（注册表、缓存、单例）逐项排查。

### 9.7 等价证明纪律（对齐官方缺口文档模式）

最终残留项逐项写证明，格式：行号+指令索引 → 变异后控制流 → 全体输入值域分析 → 下游兜底/归一化。官方文档只认可这种证明，也以此为口径判定"理论残留"。本项目的理论残留（原始分母下不可杀）：letterGrade 兜底 return "F"、scoreNumeric L246 零容差不可达、ArithmeticExpression L24/L34/L72 冗余 skipSpaces、PrefixExpressionOperation.check L68 循环边界、NumberCalculation.check L98 冗余二次判断、assessLesson L137 枚举 default（null→NPE，伪造 ordinal 属禁止层）。
